## Key decisions

Do not use insta-automation as the recipe database without an explicit product-project decision. The native project marker is a candidate, not confirmed live infrastructure.

Preserve public previews separately from protected bodies. Three free slots define the free selection. Collection release membership defines future purchase scope. Customer clients never grant themselves access.

Do not port the native chat authorization pattern or replay its migration history without reconciliation. Native source review is not permission to edit or deploy that app.

## Scope exclusions

No real recipe import, customer-facing login, favourites, Stripe checkout, production payment grants, AI chat, child profiles or Instagram automation changes.

Use synthetic users and content. Do not put dumps, secrets, signed URLs or customer records in Git.

## Ordinary implementation choices

Resolve file naming, compatible package versions, test organization and focused indexes through repository evidence. Discover CLI syntax through the installed --help output.

Do not add SECURITY DEFINER or service-role queries to avoid designing correct access rules. Do not weaken merge checks to ship the foundation.

If the project or migration authority is unresolved, complete independent local work and report the exact missing decision. Do not guess a remote target.
